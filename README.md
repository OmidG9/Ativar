# وب‌سایت آتیوار | ATIVAR

وب‌سایت سازمانی آتیوار؛ مشاوره فین‌تک، هوش مصنوعی سازمانی، معماری راهکارهای مالی دیجیتال و اجرای پروژه‌های فناوری.

## ویژگی‌ها

- فارسی و RTL با فونت محلی Vazirmatn
- Next.js 15 (App Router) + TypeScript + Tailwind CSS
- طراحی مینیمال و مسئله‌محور با تمرکز بر تبدیل بازدیدکننده به سرنخ
- متادیتای اختصاصی و Canonical برای هر صفحه، Open Graph، sitemap، robots و manifest
- داده ساختاریافته Organization و WebSite (JSON-LD)
- فرم تماس با اعتبارسنجی دوطرفه، ضداسپم (Honeypot + Rate Limit) و ارسال هم‌زمان به **بات تلگرام** و **ایمیل**
- بخش «مسئله / رویکرد / ارزش / پرسش‌های متداول» در صفحات خدمات و راهکارها، همراه با FAQ Schema
- صفحات مقاله با متادیتای اختصاصی، Article Schema و فهرست خودکار در sitemap (۱۰ مقاله در چهار دسته موضوعی)
- صفحه مطالعه موردی با الگوی استاندارد انتشار و تفکیک اطلاعات تأییدشده از اطلاعات در انتظار انتشار
- متن دکمه‌های یکپارچه از طریق `src/lib/cta.ts` و تعریف یکسان محصولات و خدمات در `src/content/service-lines.ts`
- فرم تماس با موضوعات درخواست مطابق بسته محتوا، اعتبارسنجی دوطرفه و پیام‌های شفاف موفقیت و خطا
- CI با GitHub Actions روی رانر self-hosted (برچسب `Ativar`): lint، typecheck، تست، build، ساخت ایمیج داکر و استقرار خودکار
- هدرهای امنیتی، دسترس‌پذیری پایه (Skip Link، Focus State، برچسب فرم‌ها) و احترام به `prefers-reduced-motion`

## راه‌اندازی

```bash
npm install
npm run dev
```

سایت روی `http://localhost:4646` در دسترس است.

## اجرا با داکر

```bash
cp .env.example .env.production   # مقادیر واقعی را وارد کنید
docker compose --env-file .env.production up -d --build
curl -fsS http://127.0.0.1:4646/api/health
```

- ایمیج چندمرحله‌ای است و از `output: "standalone"` نکست استفاده می‌کند؛ فقط فایل‌های لازم در ایمیج نهایی قرار می‌گیرند.
- کانتینر با کاربر غیر root اجرا می‌شود و healthcheck روی `/api/health` دارد.
- پورت `4646` روی هاست به پورت `3000` کانتینر متصل می‌شود.
- متغیرهای `NEXT_PUBLIC_*` در زمان build داخل ایمیج ثابت می‌شوند و بقیه متغیرها در زمان اجرا تزریق می‌شوند.

مستند کامل نصب رانر self-hosted و استقرار خودکار: [`deploy/README.md`](deploy/README.md).

## پیکربندی فرم تماس

فرم در `src/app/api/contact/route.ts` اعتبارسنجی می‌شود و سپس از طریق `src/lib/contact-delivery.ts` به **همه مقصدهای فعال** و به‌صورت موازی ارسال می‌گردد. فایل `.env.example` را به `.env.local` کپی کنید.

**۱) بات تلگرام (پیشنهادی برای اطلاع سریع):**

```env
TELEGRAM_BOT_TOKEN=123456:ABC...
TELEGRAM_CHAT_ID=-1001234567890
```

ربات را با BotFather بسازید، به گروه یا چت موردنظر اضافه کنید و `chat_id` را از `getUpdates` یا `@userinfobot` بگیرید.

**۲) ایمیل با Resend:**

```env
RESEND_API_KEY=re_...
CONTACT_TO_EMAIL=info@example.com
CONTACT_FROM_EMAIL=website@example.com
```

**۳) وبهوک عمومی (اختیاری):**

```env
CONTACT_WEBHOOK_URL=https://example.com/webhook
```

### رفتار ارسال

- درخواست هم‌زمان به همه مقصدهای فعال ارسال می‌شود و **اگر دست‌کم یکی موفق شود**، ثبت درخواست موفق در نظر گرفته می‌شود.
- اگر یکی از مقصدها خطا بدهد، خطا فقط در لاگ سرور (بدون اطلاعات شخصی) ثبت می‌شود و کاربر پیام موفقیت می‌بیند.
- اگر **همه** مقصدها ناموفق باشند، پاسخ `502` برگردانده می‌شود.
- اگر هیچ مقصدی تنظیم نشده باشد:
  - در محیط توسعه درخواست پذیرفته می‌شود اما ارسال نمی‌گردد (بدون ثبت اطلاعات شخصی در لاگ).
  - در production پاسخ `503` برگردانده می‌شود. هیچ موفقیت ساختگی نمایش داده نمی‌شود.

> برای آزمون محلی می‌توانید `TELEGRAM_API_BASE` و `RESEND_API_BASE` را به یک سرور mock اشاره دهید. تست‌های `tests/contact-route.integration.test.ts` همین مسیر را با HTTP واقعی پوشش می‌دهند.
> \\

### آزمایش ارسال تلگرام

۱. در تلگرام به [@ativarnotifbot](https://t.me/ativarnotifbot) پیام بدهید (دکمه Start).
۲. `npm run telegram:test` را اجرا کنید. اگر `TELEGRAM_CHAT_ID` خالی باشد، اسکریپت آن را از پیام‌های اخیر ربات پیدا می‌کند و مقدار لازم برای `.env` را چاپ می‌کند.
۳. مقدار `TELEGRAM_CHAT_ID` را در `.env` بگذارید و سرور را دوباره راه‌اندازی کنید.
۴. `npm run contact:test` یک درخواست آزمایشی به فرم می‌فرستد و باید پیام «درخواست جدید از وب‌سایت آتیوار» را در تلگرام ببینید.

اگر سایت روی پورت دیگری در حال اجراست:

```powershell
node scripts/telegram-test.mjs --form --url=http://localhost:4647/api/contact
```

> ارسال تلگرام از سمت سرور انجام می‌شود و به پورت جداگانه نیاز ندارد. سروری که سایت روی آن اجرا می‌شود باید بتواند به `api.telegram.org` دسترسی داشته باشد؛ در شبکه‌هایی که تلگرام مسدود است، از VPN/پروکسی سرور یا استقرار روی سرور خارج از محدودیت استفاده کنید. توکن ربات فقط در متغیرهای محیطی سرور نگهداری می‌شود.

> محدودیت نرخ درخواست در حافظه سرور نگهداری می‌شود. برای استقرار چندنمونه‌ای (serverless) از یک سرویس مشترک مانند Redis استفاده کنید.

## تحلیل بازدید و Search Console

به‌صورت پیش‌فرض هیچ اسکریپت تحلیلی بارگذاری نمی‌شود. برای فعال‌سازی:

```env
NEXT_PUBLIC_ANALYTICS_SRC=https://plausible.io/js/script.js
NEXT_PUBLIC_ANALYTICS_DOMAIN=ativar.ir
```

سازگار با Plausible، Umami و سرویس‌های مشابه. برای تأیید مالکیت در Google Search Console نیز می‌توانید `NEXT_PUBLIC_GOOGLE_SITE_VERIFICATION` را تنظیم کنید.

## سیاست محتوا

هیچ آمار، مشتری، مجوز یا رزومه ساختگی در سایت درج نشده است. اطلاعات ناقص با متن شفاف مشخص شده‌اند.

- ادعای «۲۵ پروژه» حذف شده و با عبارت «تجربه در طراحی و توسعه راهکارهای دیجیتال، فین‌تک و هوش مصنوعی سازمانی» جایگزین شده است؛ زیرا مبنای مستند و قابل انتساب به پروژه‌های مستقیم آتیوار تأیید نشده بود.
- نتایج عددی، نام کارفرما و جزئیات فنی مطالعه موردی تا دریافت مستندات و مجوز انتشار درج نمی‌شوند.
- عنوان شغلی و رزومه اعضای تیم تا تأیید سمت رسمی و سوابق مستند، «در انتظار تأیید» مشخص می‌شود و تجربه حرفه‌ای اعضا به آتیوار نسبت داده نمی‌شود.
- صفحات خدمات از وعده نتیجه قطعی و آمار بدون منبع پرهیز می‌کنند و تحقق نتایج را به شرایط سازمان وابسته می‌دانند.
- CTAها از فهرست واحد `src/lib/cta.ts` خوانده می‌شوند تا عبارت‌های هم‌معنا و پراکنده ایجاد نشود.

## بازنگری محتوا

محتوای صفحات بر اساس بسته بازنگری (`ativar-prompt.md`) به‌روزرسانی شده است: صفحه اصلی، مشاوره و تحول دیجیتال، هوش مصنوعی سازمانی، AI Workspace، فین‌تک، معماری و اجرای پروژه، پروژه‌ها، تیم، بینش‌ها و تماس. جزئیات بخش‌به‌بخش و تصمیم‌های محتوایی در `PROJECT_PLAN.md` (بخش ۷) ثبت شده است.
